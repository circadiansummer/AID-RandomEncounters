## Overview

Random Encounters lets players and scenario creators build a pool of custom events that the script can introduce throughout an AI Dungeon adventure. Handcraft encounters you want players to experience while letting the AI decide how those moments fit into the story.

### Short Version?

1. Write possible events in **Encounter Story Cards**, or let the AI suggest them.
2. Set their **Rarity**, **Duration**, and optional **Act** requirements.
3. Play normally. Random Encounters chooses eligible events at intervals set by **Encounter Pacing**, then asks the AI to introduce them naturally.
4. The script records the result on each card. Completed encounters retire; unsuccessful encounters return to the pool for another chance.

### An example

A creator might write the following in the **Entry** of `RAND_01`:

~~~text
A traveling merchant offers the player a strangely inexpensive magical potion.
~~~

Later in the adventure, the AI might introduce the event with something like:

> As you reach the crossroads, a merchant waves from beneath a brightly patched awning. "A rare potion, just for you," she calls, offering a tiny blue bottle at an almost suspiciously low price.

This is an **illustration**, not a fixed response. The AI adapts the encounter to the current scene and may establish it gradually over several turns instead of interrupting ongoing action.

This can be adapted to fit multiple genres or scenario styles: 

> **Fantasy RPG:** A bandit ambush, a friendly roadside merchant, a dragon flying overhead, or a magical mishap.
>
> **Slice of life:** A rumor about the player or an NPC, two rivals crossing paths, an unexpected social event, or the return of a long-lost childhood friend.

# Getting Started

## What you need to know

- **Four script sections are required:** Library, Input, Context, and Output.
- **Encounter content lives in Story Cards:** use the `RAND_##` cards generated by Random Encounters.
- **The current card format is required:** old Config, encounter, and runtime layouts are not automatically converted. Start a fresh adventure when installing a new script version.

You can write every encounter yourself, let the AI populate untouched placeholder cards, or mix both approaches.

## 1. Install the script

In AI Dungeon, open your Scenario's scripting editor and enable scripting. Copy the contents of each linked file into its matching section:

| AI Dungeon section | Script file |
| --- | --- |
| Library | [`Library.js`](https://github.com/circadiansummer/AID-RandomEncounters/blob/main/Library.js) |
| Input | [`Input.js`](https://github.com/circadiansummer/AID-RandomEncounters/blob/main/Input.js) |
| Context | [`Context.js`](https://github.com/circadiansummer/AID-RandomEncounters/blob/main/Context.js) |
| Output | [`Output.js`](https://github.com/circadiansummer/AID-RandomEncounters/blob/main/Output.js) |

Save the Scenario and start a **new Adventure**. In this development candidate, the first eligible action creates the **Config** Story Card only. To generate blank encounter cards, set **Create Placeholder Cards** to `true` in Config and take another action; by default, that adds `RAND_01`–`RAND_04` and resets the toggle to `false`. You may also author your own `RAND_##` cards without requesting placeholders.

If you already use other scripts, don't paste multiple complete `modifier(text)` wrappers into the same Input, Context, or Output section. The scripts' calls must be combined appropriately. See [Compatibility](#script-compatibility).

## 2. Write your encounters

First create an encounter card manually or set **Create Placeholder Cards: true** in Config and take an in-game action to add the default four placeholders. Then open a card and replace its **Entry** placeholder:

~~~text
[Define random encounter 01 here.]
~~~

with an event you want to be possible in the story:

~~~text
The town's annual festival begins earlier than anyone expected, forcing two rival families into the same crowded square.
~~~

The title can be customized. Keep the card's `RAND_01` key and its script-managed **Encounter State** fields intact.

Each card also has editable **Encounter Settings** in its Notes:

~~~text
============ ENCOUNTER SETTINGS ============
--------- PROGRESSION ---------
- Act: 1
- Importance: Required
---------- BEHAVIOR ----------
- Rarity: Common
- Duration: Default
~~~

Only change the settings you mean to customize; the script manages **Status** and **Encounter Number**.


**Importance: ASAP (v1.12, per-card Notes):** Set `- Importance: ASAP` to make an encounter Required for Act progression and schedule it at the first eligible story opportunity, bypassing ordinary pacing. It does not bypass Act locks, First Encounter Turn scheduling, an Active or unresolved encounter, or other scripts' generation tasks. Rarity is configured independently. The earlier development-only `Force ASAP` setting is retired.

## 3. Adjust Config

The **Config** Story Card controls the adventure-wide system. For most players, the important options are:

| Setting | Purpose |
| --- | --- |
| **Enabled** | Turn automatic encounters on or off. |
| **Encounter Pacing** | Choose how many turns generally pass between encounter opportunities (Very Fast through Very Slow). |
| **First Encounter Turn** | Set `0` for standard behavior, `5` for the first automatic encounter on RE turn 5, or `5-10` to choose a random first turn from that inclusive range. |
| **Maximum Encounter Cards** | Set the highest numbered card to create. |
| **Create Max Encounter Cards** | Set to `true` to make any missing cards up to that maximum; resets afterward. |
| **Populate Placeholder Cards** | Set to `true` to ask the AI to fill untouched cards; retries automatically until complete. |
| **Current Act** | The highest Act that can currently be selected. |
| **Encounter Difficulty / Encounter Theme** | Guide AI-generated placeholder encounters without prescribing a genre or outcome. |
| **Bypass Situational Awareness** | Ask the AI to introduce the selected encounter immediately; actual model compliance may vary. |
| **Use Advanced Settings** | Unlock editable pacing intervals, rarity weights, and duration values. |

Config also provides Global Defaults for newly created or reset cards, plus one-shot tools to restore defaults or return encounters to Available.

# Features & Customization

## Act progression — control when events become available

Divide the encounter pool into numbered **Acts**. Act 1 is available from the start; later Acts unlock as Required encounters are completed.

- **Required:** All Required encounters assigned to the current Act must complete successfully before progressing.
- **Optional:** These encounters do not block progression.
- **Earlier Acts:** Any earlier-Act encounter that is still Available can remain in the pool after the next Act unlocks.

You might put small quests in Act 1, a required boss encounter in Act 2, and the aftermath in Act 3. Acts can also create loose story sequences without dictating exactly how the AI must tell the story.

Encounter cards are grouped under `#RE - Act X Encounters  📜` for unlocked Acts and `#RE - Act X Encounters  🔒` for future Acts. These categories update when Acts progress; the older Act & Encounter Map feature is retired.

## First Encounter Turn — schedule your opening event

Set **First Encounter Turn** under **ENCOUNTERS** in the Config Story Card:

- `0` (default): The first event uses normal Encounter Pacing, unchanged from v1.0.
- `5`: The first **automatic** encounter is scheduled for RE story turn 5.
- `5-10`: One turn between 5 and 10 (inclusive) is selected once; the countdown leads to that turn.

After that first automatic encounter is selected, every later encounter uses ordinary Encounter Pacing and Duration. Manual `/RE start` commands bypass this first-turn setting and do not consume its one-time automatic schedule. If no eligible card exists or an encounter/other script is already occupying the scheduled turn, RE waits until an eligible normal story turn and then proceeds. Only counted RE story turns matter; paused and disabled turns do not spend the countdown.

**Verification:** The owner confirmed the final 📜/🔒 category UI and first-eligible ASAP scheduling in AI Dungeon. See [v1.12 release notes](docs/RELEASE_NOTES_v1.12.md) for remaining unverified history and partial-generation Retry behavior.

## Rarity, pacing & duration — adjust the rhythm

These settings do different jobs:

| Setting | What it changes |
| --- | --- |
| **Rarity** | The relative odds of choosing an eligible card: Very Common, Common, Rare, or Very Rare. |
| **Encounter Pacing** | The number of story turns between encounter opportunities: Very Fast, Fast, Moderate, Slow, or Very Slow. |
| **Duration** | How long an Active encounter has to develop before the script checks its outcome. |

Enable **Advanced RE Settings** to edit the numerical values behind these presets.

## What happens when an encounter ends?

The script asks the AI to classify the event, then stores its conclusion under **Outcome** in that encounter's Entry.

| Result | What Random Encounters does |
| --- | --- |
| **Occurred** | Marks the encounter complete (**Retired**) and saves the Outcome. A Required success may unlock the next Act. |
| **Did not occur** | Saves the Outcome and returns the card to **Available**, so it can be selected later. |
| **Still in progress** | Gives the event additional time as **Awaiting Completion**. After five consecutive incomplete checks, it returns to Available. |

You don't need to write these classifications yourself during normal gameplay. The script handles the behind-the-scenes resolution instructions.

After resolution, the pacing countdown resumes. **Outcomes stay on individual Encounter Cards**; there is no separate History card.

# Let the AI Create Encounters

## Populate Placeholder Cards

Don't want to handwrite every event? **Populate Placeholder Cards** asks the AI to create setting-appropriate encounter ideas, each limited to **one sentence**, without imposing a genre or tone.

### How to use it

1. In **Config**, set **Placeholder Cards to Create** to the number of **additional** blank cards you want (default 4).
2. Set **Create Placeholder Cards** to `true` and take an in-game action. That creates the requested cards and resets the one-shot setting to `false`.
3. Set **Run Encounter Generation** to `true`.
4. Take another in-game action and follow the on-screen messages. Continue as needed until generation finishes.

The script fills only cards whose Entry still contains the untouched default placeholder. Your custom Entries, titles, and encounter settings are preserved. When generation finishes, the toggle resets to `false`.

You may see:

~~~text
RE - Encounter population in progress - Attempt 1.
~~~

When new card data is being applied, the story may show:

~~~text
[RE] Updating Encounter Cards (X of Y) - Hit Continue
~~~

Choose **Continue** to resume play. If the AI does not produce card data on an attempt, Random Encounters retains the request and tries again on a later eligible action.

# Manual Commands

Enter these commands as your AI Dungeon action when you want to manage encounters directly:

| Command | What it does |
| --- | --- |
| `/RE help` | Show available commands. |
| `/RE status` | Show the current countdown or encounter state in a popup, without advancing the story. |
| `/RE on` / `/RE off` | Enable or disable automatic encounters. |
| `/RE start` | Queue a random eligible encounter. |
| `/RE start 3` | Queue a specific Available encounter, such as `RAND_03`. |
| `/RE end` / `/RE stop` | End the current Active encounter and queue resolution. |
| `/RE reset 3` | Reset a specific encounter to Available using current Global Defaults; clear its Outcome. |
| `/RE reset all` | Reset all encounters to Available using current Global Defaults; clear their Outcomes. |

Commands do **not** consume Random Encounters story turns. Starting a new encounter while one is Active ends the old one and queues its resolution.

# Script Compatibility

Random Encounters has been **tested with Inner Self and Auto-Cards**. The repository includes a [combined Inner Self/Auto-Cards testing setup](https://github.com/circadiansummer/AID-RandomEncounters/tree/main/RE-InnerSelf-Merge) containing Library, Input, Context, and Output files for creators who need to compose those scripts.

**Note:** With Inner Self or Auto-Cards active, **Populate Placeholder Cards may take additional turns**. You can populate cards without the other scripts active, or keep the combined setup and allow retries. One previous combined test successfully filled all four cards on its eleventh generation attempt; that isn't a fixed number of required turns.

Compatibility tests cover known combinations, not every possible script or load order. For implementation details, see the [compatibility guide](https://github.com/circadiansummer/AID-RandomEncounters/blob/main/docs/compatibility.md).

# Troubleshooting

### My encounters aren't appearing

Check that **Enabled** is `true`, the Encounter Cards exist, and their **Status** is Available. The card must also be assigned to an Act at or below **Current Act**. Encounter Pacing may mean several turns pass before the next opportunity.

If you need a quick check, use `/RE start 1` with a suitable Available card.

### The encounter didn't happen immediately

This can be expected. Random Encounters asks the AI to introduce events *when the story allows*, rather than abruptly interrupting dialogue or actions. An encounter can take several turns to develop.

If it ultimately does not occur, it can return to the pool.

### Populate Placeholder Cards is taking longer than expected

Leave the setting enabled and keep playing. The script automatically retries unfinished cards and reports numbered attempts. Generation may take longer with Inner Self or Auto-Cards active. Cards you've already written aren't overwritten.

### A card I edited didn't change

**Populate Placeholder Cards** only targets Entries that still contain the exact default placeholder. If you've replaced that placeholder with your own content, the card is intentionally protected.

### My old Config or Encounter Cards aren't being updated

Random Encounters no longer migrates older card schemas. Use the current script with a **new Adventure** and the current card layout; don't expect existing obsolete Story Cards to be converted.
